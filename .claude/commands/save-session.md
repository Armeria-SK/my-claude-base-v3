# Save Session - セッション状態の保存とレポート生成

セッションの区切り（作業ブロック終了・/compact 前・終業時）に実行する。この会話の内容と git の実際の状態を素材に、人間向けレポートを作る。

## Usage
```
/save-session          # 現在のセッションを保存
```

## Process（順に実行）

### 1. 素材を集める
何をしたかは、記憶ではなく記録を正とする: `git status` / `git log`（この作業ブロックのコミット）/ `git diff --stat`、`plans/` の PLAN.md、この会話の内容。作業の一行ログはフックでは取っていない（git と会話記録で足りるため）。

### 2. 人間向けレポートを当日ジャーナル（`tasks/YYYY-MM/DD.md`、今日の日付）末尾に追記
`tasks/` や当日のファイルが無ければ作る（新規ファイルの1行目は `# YYYY-MM-DD 作業ジャーナル`）。ジャーナルに書き込むフックは無く、レポートだけが入る。
見出しは**結論を1行で**。平易な日本語（直訳ジャーゴン禁止）、各項目1行、ファイル一覧や技術詳細は書かない（git に残っている）。

```markdown
## HH:MM セッションレポート — <結論1行: 何がどうなったか>

**現在地**: <ブランチ> @ <短縮SHA>
**やったこと**: <1-3行。成果と検証結果（PASS/FAIL/未検証）>
**できなかったこと・保留**: <未完・見送り。無ければ「なし」>
**確認してほしいこと**: <ユーザーの判断が要る事項。スコープ外の提案もここ。無ければ「なし」>
**次にやること**: <次セッションの最初の一手から順に、最大5行>
```

### 3. deviations の提案化（あれば）
`plans/{slug}/deviations.md` に記載があれば、「範囲外だが価値がありそうな変更」として「確認してほしいこと」に**提案として**まとめる。実装はしない。

### 4. 教訓の受け箱と todo の整理
`tasks/lessons.md` は受け箱（書き方と置き場所の表は CLAUDE.md §4）。入っている項目を古い順に1件ずつ、置き場所へ送る。

- **送る**: §4 の表から置き場所を1つ選び、作業ブランチでそこを直す（PR はリポジトリごと・save-session 1回につき1本）。`git fetch` のあと、項目に `- Routed: <file> — "<書いた行そのまま>" (PR #N)` を足す。
  - すでにどこかに書いてある決まりは新しく書かない。`file:line` を添えて「保管のみ」にする。
  - `- Recurrence of:` の付いた項目（同じ決まりの繰り返し）は新しい文として送らない。1回目は今ある文をその場所で締める（短く・前のほうに・きっかけを具体的に）。2回目は、機械で止める仕組み（hook）を、かかる手間を添えて持ち主に提案する。
  - hook はこの手順では作らない。「確認してほしいこと」に載せる。
- **受け箱から出す**: 先に項目の全文を `tasks/lessons-archive.md` の末尾へそのまま写す。出してよいのは次の4つだけ。
  - 移した: PR がマージ済みで、記録した行が `git fetch` 後の `origin/main` で grep できる → `- Moved: <date> → <file>`（持ち主に聞かない）
  - 保管のみ: 決まりがすでに定義か hook にある（`file:line` を書く）（聞かない）
  - 断られた: 持ち主がその項目・PR・仕組みを断った → `- Declined: <date> (<持ち主の言葉>)`（聞かない）
  - もう当てはまらない（道具が古い、決定が置き換わった）: レポートに載せ、持ち主が「はい」と言ってから出す
- **todo**: 未完は `tasks/todo.md` の `## Now` / `## Backlog` に1行、完了は `## Recently Done`（上限10）。上限からあふれた完了の行と、ほかの行や計画に置き換えられた行は、`tasks/todo-archive.md` の末尾へそのまま写してから消す。
- **レポートの「確認してほしいこと」に載せる**: 仕組み（hook）の提案、「もう当てはまらない」の候補、PR のマージ待ちで受け箱に残っている項目。
- （移行が終わるまで）`plans/memory-rebuild/routing.md` に載っている 50 件は、持ち主が認めた行のとおりにだけ動かす。2026-11-18 の時点で `tasks/todo.md` にある行は、持ち主が `plans/memory-rebuild/todo-routing.md` の行を認めるまで、消さず・書き換えない。

## Rules
- レポートの「現在地」と4項目は固定。「できなかったこと・保留」は空でも「なし」と明記
- ジャーナルは追記のみ。既存行の書き換え・削除はしない
- 同じ内容を2箇所に書かない（次にやること＝レポート、履歴＝git）
- **増分だけ書く**（CLAUDE.md §4）: 書く前に既出（直近のレポート・todo・lessons）を読み、新しく得たものだけ記す。既出を言い換えて二重に書かない（記録が膨らむ上、次のセッションが新しい進展と読み違える）。ただし上の固定項目（現在地＋4項目）は省略しない — 新しい中身が無い項目は「なし」と書く
