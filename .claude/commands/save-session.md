# Save Session - セッション状態の保存とレポート生成

セッションの区切り（作業ブロック終了・/compact 前・終業時）に実行する。この会話の内容と git の実際の状態を素材に、人間向けレポートを作る。「/save-session 補完」なら、クラッシュ等でレポートを作りそびれた過去セッションを後追いで作る（SAVE マーカーはその過去セッションの ID で書く）。

## Usage
```
/save-session          # 現在のセッションを保存
/save-session 補完      # レポート未生成の過去セッションを補完
```

## Process（順に実行）

### 1. 素材を集める
何をしたかは、記憶ではなく記録を正とする: `git status` / `git log`（この作業ブロックのコミット）/ `git diff --stat`、`plans/` の PLAN.md、この会話の内容。作業の一行ログはフックでは取っていない（git と会話記録で足りるため）。`tasks/` が無ければ作る。
「補完」の場合は、対象セッションの会話記録（`~/.claude/projects/<プロジェクト>/<ID>*.jsonl`）を、必要な範囲だけ検索して読み、同じ期間の git log と突き合わせる。

### 2. 人間向けレポートを当日ジャーナル（`tasks/YYYY-MM/DD.md`、今日の日付）末尾に追記
見出しは**結論を1行で**。平易な日本語（直訳ジャーゴン禁止）、各項目1行、ファイル一覧や技術詳細は書かない（git に残っている）。

```markdown
## HH:MM セッションレポート — <結論1行: 何がどうなったか>

**現在地**: <ブランチ> @ <短縮SHA>
**やったこと**: <1-3行。成果と検証結果（PASS/FAIL/未検証）>
**できなかったこと・保留**: <未完・見送り。無ければ「なし」>
**確認してほしいこと**: <ユーザーの判断が要る事項。スコープ外の提案もここ。無ければ「なし」>
**次にやること**: <次セッションの最初の一手から順に、最大5行>
```

### 3. deviations の提案化（あれば）
`plans/{slug}/deviations.md` に記載があれば、「範囲外だが価値がありそうな変更」として「確認してほしいこと」に**提案として**まとめる。実装はしない。

### 4. SAVE マーカーを追記
当日ジャーナル末尾に1行（ID は注入されたもの。補完モードでは対象過去セッションの ID）:
```
- HH:MM:SS [xxxxxxxx] SAVE
```

### 5. lessons / todo の反映
得た教訓は `tasks/lessons.md` に `### [date] パターン名` + Trigger / Mistake / Fix / Rule で末尾追記（このリポジトリ固有・苦労して得たものだけ）。未完タスクは `tasks/todo.md` の `## Now` / `## Backlog` に1行、完了は `## Recently Done`（上限10）へ。

## Rules
- レポートの「現在地」と4項目は固定。「できなかったこと・保留」は空でも「なし」と明記
- ジャーナルは追記のみ。既存行の書き換え・削除はしない
- 同じ内容を2箇所に書かない（次にやること＝レポート、履歴＝git）
